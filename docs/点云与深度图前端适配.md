# 点云与深度图前端适配

## 当前实机数据与两层消息

2026-10-22 使用当前奥比设备检查 ROS 2 图。以下数值是**这台设备当时的实测值**，不是对所有雷达或相机的硬编码约束：

| 来源 | 话题 | 类型与实测布局 |
| --- | --- | --- |
| 彩色图 | `/camera/color/image_raw` | `sensor_msgs/msg/Image`，`rgb8`，1280×720，`step=3840` |
| 深度图 | `/camera/depth/image_raw` | `sensor_msgs/msg/Image`，`16UC1`，848×480，`step=1696`；`0` 和 `65535` 作为无效值处理 |
| 源点云 | `/camera/depth/points` | `sensor_msgs/msg/PointCloud2`，`x/y/z` 为 `FLOAT32` (`datatype=7`)，偏移 0/4/8，`point_step=16`，小端；第 12–15 字节是填充或其他数据，不能当作第 4 个坐标 |
| 软件内部点云预览 | `/calibration/camera/streams/points` | `PointCloud2`，只保留有效 `x/y/z`，偏移 0/4/8，`point_step=12`，单位米，`header.frame_id` 沿用源点云；预览会抽样，不能把它当成完整雷达数据用于外参求解 |
| 软件内部深度预览 | `/calibration/camera/streams/compressed` | `CompressedImage`，`format=jpeg`，`header.frame_id=depth_image`；这是伪彩预览，不是原始深度数值 |

源点云也可以由雷达发布，不需要是深度相机。点云的 `header.frame_id` 是坐标系名；图像与雷达的坐标系可以不同，外参标定必须使用原始消息中的坐标系与时间戳。当前 3D 控件只做观察，不对多帧做 TF 运动补偿。

## 界面怎样选

首页有三项独立输入：**RGB 图像**、**深度图**、**点云话题**。它们的 `config/calibration.yaml` 默认字段分别为 `topic_input.name`、`topic_input.depth_image_name`、`topic_input.pointcloud_name`，均可留空；在界面刷新并选择时，以实际 ROS 图中的完整话题名为准。至少选一路。RGB 图像与深度图不能选择同一个话题。

“信息流”可勾选 RGB、深度图、3D 点云中的一路或多路；只有单选可标定的 RGB 才能进入单目内参。深度图默认支持 `16UC1`（毫米）和 `32FC1`（米）的**原始** `Image`，使用固定 0.2–5 m 色阶生成伪彩画面，非法值显示为黑色。`compressedDepth` 不按普通 JPEG 解码，也不会出现在深度图选择项；如果发布端只有 `compressedDepth`，应让驱动同时发布原始深度 `Image`，或先加专门的解码适配器。

“叠加帧数”默认值来自 `calibration_ui.cloud_accumulation_frames`，范围 1–30，界面可直接更改。它把最近 N 帧点云叠加在**3D 预览**里，并把绘制总量限制在约 48000 点。值增大时预览更密，达到绘制上限后会抽样；传感器运动、雷达扫描或物体运动可能造成拖影。它不改变源消息、不保存叠加结果，也不参与外参标定。3D 视图使用各轴 5%–95% 分位范围构图，避免远处离群点把主体缩成小点；落在当前视图外的预览点会被裁剪。

## `PointCloud2` 正确解码规则

不要假设一条点就是连续 12 字节。必须读取消息中的 `fields`、`point_step`、`row_step`、`width`、`height`、`is_bigendian`：

1. 从 `fields` 按 **name** 找 `x`、`y`、`z`，分别读取各自的 `offset`、`datatype`、`count`。字段顺序可变，消息还可能带 `intensity`、`ring`、`time`、`rgb`。
2. 本程序接受三个坐标字段各为 `FLOAT32` (`7`) 或 `FLOAT64` (`8`)、`count=1`、小端。每个字段的 `offset + 字节数` 不得超出 `point_step`。其他类型需要在解码器中增加对应读取分支。
3. 第 `(row,col)` 个点的起始地址是 `data + row * row_step + col * point_step`，不是 `data + 索引 * 12`。先验证 `row_step >= width * point_step`、`data.length >= height * row_step`。
4. 按字段偏移读取浮点数；跳过 `NaN`、无穷和 `(0,0,0)` 占位点。**不要过滤 `z<=0`**：雷达坐标系中地面和下方的有效点可能具有非正 Z。保留消息的 `header.stamp`、`header.frame_id`，不要把雷达坐标误认为相机坐标。
5. 预览可抽样并限制绘制点数；算法输入应另行消费**原始点云话题**，不应使用 `/calibration/camera/streams/points` 这个已抽样的预览话题。

浏览器前端若通过 rosbridge 收到 `data`，先将其转换为 `Uint8Array`（rosbridge 可能传 base64；具体取决于传输层），再按下面的字节规则解码：

```ts
type Field = { name: string; offset: number; datatype: number; count: number };
type Cloud = {
  width: number; height: number; point_step: number; row_step: number;
  is_bigendian: boolean; fields: Field[]; data: Uint8Array;
};

function decodeXYZ(msg: Cloud, maxPoints = 12000): Float32Array {
  if (msg.is_bigendian || msg.point_step <= 0 ||
      msg.row_step < msg.width * msg.point_step ||
      msg.data.byteLength < msg.height * msg.row_step) return new Float32Array();
  const xyz = ['x', 'y', 'z'].map(name => msg.fields.find(f => f.name === name));
  if (xyz.some(f => !f || f.count !== 1 || ![7, 8].includes(f.datatype) ||
      f.offset + (f.datatype === 7 ? 4 : 8) > msg.point_step)) return new Float32Array();
  const view = new DataView(msg.data.buffer, msg.data.byteOffset, msg.data.byteLength);
  const result: number[] = [];
  const total = msg.width * msg.height;
  const stride = Math.max(1, Math.ceil(total / maxPoints));
  for (let i = 0; i < total; i += stride) {
    const base = Math.floor(i / msg.width) * msg.row_step +
                 (i % msg.width) * msg.point_step;
    const p = xyz.map(f => f!.datatype === 7
      ? view.getFloat32(base + f!.offset, true)
      : view.getFloat64(base + f!.offset, true));
    if (p.every(Number.isFinite) && p.some(v => v !== 0)) result.push(p[0], p[1], p[2]);
  }
  return new Float32Array(result);
}
```

本项目对应实现：源点云解码在 `src/bridge/io_node.cpp` 的 `receiveCloud()`；界面内部预览解码在 `src/bridge/calibration_ros_client.cpp` 的 `stream_cloud_sub_` 回调；3D 绘制与多帧叠加在 `src/ui/point_cloud_view.cpp`。如果你的雷达用整数毫米坐标或大端格式，应在 **`receiveCloud()`** 增加该 datatype/字节序的转换，并写明坐标单位；前端浏览器实现也按上述规则增加对应分支。不要只修改点云界面的颜色或缩放。

## 实机定位命令

```bash
source /opt/ros/humble/setup.bash
ros2 topic list -t | grep -E 'image_raw|points'
ros2 topic info -v /你的点云话题
ros2 topic echo --once /你的点云话题 --field fields
ros2 topic echo --once /你的点云话题 --field point_step
ros2 topic echo --once /你的深度图话题 --field encoding
```

若有话题但预览为空，先看发布者数量与 QoS，再核对 `fields`、`point_step`、`row_step`、字节序和有效点数量。当前奥比实测源点云 `point_step=16`，软件内部预览 `point_step=12`；这两个数不同是预览重新打包的正常结果。
