# 换机编译与测试说明

## 本机故障结论（2026-10-20）

本项目是 ROS 2 包 `danmucamera`，源码目录叫 `qiji`。本机曾在激活 Miniforge `base` 环境时执行构建，出现两层故障：

1. CMake 选中 `/home/cyf/VLA/miniforge3/bin/python3`（Python 3.14），该解释器没有 `catkin_pkg`，在 `ament_package()` 阶段报 `ModuleNotFoundError: No module named 'catkin_pkg'`。
2. 改用系统 Python 后，旧 CMake 缓存仍指向 Conda 的 `fmt` 和 `spdlog`，链接时又加载 Conda 的 `libcurl`、`libicu`，出现 `CURL_OPENSSL_4`、`CXXABI_1.3.15` 未定义引用。

已修正 `launch/build.sh`：默认指定系统 Python；检测到 Conda 环境时，从构建进程的 `PATH` 中移除该环境，并在 CMake 缓存含 Conda 路径时清理此包的旧构建目录。本机重新执行 `./launch/build.sh` 后结果为 `Summary: 1 package finished`，四个可执行目标均构建成功，RealSense 与 Orbbec 后端均启用。图形程序和 ROS 节点也已启动验证；本机相机节点成功打开 Gemini 设备。没有验证标定精度或完成整套采图流程。

## 新电脑准备

以下一键流程支持 **Ubuntu 22.04/24.04** 上已安装的 **ROS 2 Humble 或 Jazzy**，均需 amd64/arm64。它优先使用电脑已有的发行版，包括已装 Jazzy 的电脑；只有完全没有 ROS 时，才按 Ubuntu 22.04→Humble、24.04→Jazzy 补装。不会为了匹配 Ubuntu 版本再装第二套 ROS。复制项目后，在新电脑的图形桌面终端运行（首次补装需要联网和 sudo 密码）：

```bash
cd /你的路径/qiji && ./launch/setup_and_run.sh
```

脚本先检测已安装的软件，只补齐缺少的 Qt 6、OpenCV、colcon、ROS 2 和依赖，并按 USB 设备自动检测 Orbbec/RealSense 相机。检测到 Orbbec 时，会安装所选 ROS 发行版的 `ros-<发行版>-orbbec-camera`（自带 SDK v2），并且仅在缺失时新增厂商 udev 权限规则；检测到 RealSense 时，会安装开发库和 udev 规则。相机暂时没有插上但需要预装时，用 `./launch/setup_and_run.sh --camera=orbbec`、`--camera=realsense` 或 `--camera=all`。只检查缺项而不安装、编译或启动，可用 `./launch/setup_and_run.sh --check`。如有多个 ROS 安装，可明确运行 `./launch/setup_and_run.sh --ros=jazzy`；指定未安装的发行版时脚本会停下，不会补装第二套。

首次成功编译后，脚本会在应用菜单和可用的桌面目录生成“相机标定工作台”图标。以后双击图标即可启动，启动失败时终端会停留以显示错误。桌面环境若仍将图标标为不受信任，在图标右键菜单选择“允许启动”；也可手动运行 `./launch/create_shortcut.sh` 重新尝试创建缺失的图标。图标记录项目绝对路径，移动项目后需在新路径重新生成。

安装过程**不会升级或卸载已安装的软件包**，也不会改写 `.bashrc`、`.zshrc`、Conda/venv 或已存在的软件源与 udev 规则。只在缺失时添加 ROS/RealSense 软件源和 Orbbec 规则；构建产物只写入本项目的 `build/`、`install/`、`log/`。如果现有软件版本与新包冲突，脚本会停止并显示 apt 错误，不会强行改动原环境。脚本的 Snap/Conda 路径过滤只作用于本次运行进程。其他 Ubuntu 版本和发行版会在安装前停止。

若要手动安装，先安装与系统对应的 ROS 2 发行版并完成官方环境配置，再安装构建依赖（下例为 Ubuntu 22.04/Humble）：

```bash
sudo apt update
sudo apt install build-essential cmake python3-colcon-common-extensions \
  python3-catkin-pkg python3-ament-package \
  ros-humble-ament-cmake ros-humble-rclcpp ros-humble-rcl-interfaces \
  ros-humble-sensor-msgs ros-humble-std-msgs ros-humble-std-srvs \
  ros-humble-launch ros-humble-launch-ros \
  qt6-base-dev libopencv-dev libopencv-contrib-dev v4l-utils
```

普通 V4L2 摄像头不需要厂商 SDK。已有 SDK 会被保留并优先使用；只有缺少且对应相机被检测到或通过 `--camera` 指定时才补装。SDK 缺失只会关闭对应后端，不影响 V4L2 编译。安装 SDK 后若设备仍未被识别，请重新插拔相机。新电脑上的自定义 SDK 若不在系统搜索路径，可设置 `CMAKE_PREFIX_PATH` 指向其安装前缀。

## 复制与编译

复制本目录的 `CMakeLists.txt`、`package.xml`、`src/`、`config/`、`launch/`、`docs/` 和 `README.md`。不要复制 `build/`、`install/`、`log/`；它们包含旧电脑的绝对路径。`samples/` 和 `result/` 是个人数据，按需复制。项目路径允许变化。

```bash
cd /你的路径/qiji
./launch/build.sh
./launch/run.sh
```

`build.sh` 和 `run.sh` 先用 `QIJI_ROS_DISTRO` 或当前加载的 ROS；未指定时检测已安装的发行版，多套并存且无法确定时按系统默认版本选择。`build.sh` 默认使用 `/usr/bin/python3`；如果 ROS 2 安装方式需要另一解释器，先确认它能执行 `import catkin_pkg, ament_package`，再设置 `ROS_PYTHON_EXECUTABLE=/该解释器的绝对路径`。需要彻底重编译时，可在项目根目录删除本地产物后再构建：

```bash
rm -rf build install log
./launch/build.sh
```

## 验收顺序

1. 构建输出应有 `Summary: 1 package finished`；`install/danmucamera/lib/danmucamera/` 下应有 `io_node`、`calibration_bridge`、`calibration_ui`、`calibration_solver`。
2. 运行 `./launch/run.sh` 后，终端应出现三个节点的 `process started`，并显示标定界面。关闭界面时，其余两个节点会随之退出。请在有桌面会话和显示权限的终端运行。
3. 用 `v4l2-ctl --list-devices` 确认普通摄像头可见；厂商相机先用 SDK 自带示例验证采流，再在界面中刷新、选择设备和分辨率、连接并启动，确认出现实时画面。
4. 导入测试图片或拍摄几张图片，检查预览、保存和标定结果。新相机、每种分辨率以及 RGB/红外成像器都应分别标定。

如构建输出缺少 `RealSense SDK backend enabled` 或 `Orbbec SDK v2 backend enabled`，表示对应开发库未被 CMake 找到。检查 SDK 的头文件、动态库及 `CMAKE_PREFIX_PATH`，然后删除 `build/danmucamera/` 再编译。

## 常见报错

| 现象 | 处理 |
| --- | --- |
| `No module named 'catkin_pkg'` | 用 `/usr/bin/python3 -c 'import catkin_pkg, ament_package'` 检查系统 Python；安装上面的 Python 包，重新运行 `build.sh`。 |
| `CURL_OPENSSL_4` 或 `CXXABI_1.3.15` 链接错误 | 检查 Conda 是否污染 `PATH`、`CMAKE_PREFIX_PATH`、`LD_LIBRARY_PATH`；退出 Conda，删除 `build/danmucamera/`，重新构建。 |
| `libpthread.so.0: undefined symbol: __libc_pthread_init, version GLIBC_PRIVATE`，路径在 `/snap/core20/` | Snap 版编辑器的终端把 Snap 自带 glibc 放进了动态库搜索路径。更新项目后用 `./launch/run.sh` 启动；脚本会过滤 Snap 库路径。若仍报错，运行 `./launch/build.sh` 重新编译；仍有问题时检查 `LD_LIBRARY_PATH` 和 `readelf -d install/danmucamera/lib/danmucamera/calibration_ui` 的 `RUNPATH`。 |
| `could not connect to display` / Qt `xcb` 或 `wayland` 错误 | 在已登录的图形桌面终端运行 `./launch/setup_and_run.sh`，它会补齐 Qt 平台插件并检查动态库。不要用 `sudo` 启动界面。若仍失败，运行 `QT_DEBUG_PLUGINS=1 ./launch/run.sh`，保存终端完整输出；同时检查 `DISPLAY`、`WAYLAND_DISPLAY` 和 `XDG_RUNTIME_DIR`。 |
| ROS `Error creating socket: Operation not permitted` | 容器或沙箱禁止网络套接字；在允许 ROS 2 DDS 通信的正常桌面环境运行。 |
| 设备存在但无图像 | 检查 USB/udev 权限、SDK 示例、分辨率和帧率、设备是否被其他程序占用。 |
| 已有软件源或软件版本冲突 | 一键脚本会停下并保留现有配置；查看 apt 报错，确认冲突软件版本后再手动处理。 |

ROS 软件源步骤参考 [ROS 官方安装文档](https://github.com/ros2/ros2_documentation/blob/rolling/source/Get-Started/Installation/Ubuntu-Install-Debs.rst)；Orbbec SDK 和 udev 规则参考 [Orbbec ROS 2 安装说明](https://github.com/orbbec/OrbbecSDK_ROS2)；RealSense 软件源参考 [RealSense Linux 安装说明](https://github.com/realsenseai/librealsense/blob/master/doc/distribution_linux.md)。

构建日志在 `log/latest_build/`，运行日志在 `log/ros/`。提交求助信息时附上对应日志、Ubuntu/ROS 版本和所用相机型号。

如果连脚本的解释器都因 `/snap/core20/` 动态库报错，应从系统自带终端启动；或只在当前终端执行 `unset LD_LIBRARY_PATH LD_PRELOAD` 后重试。脚本不会修改终端启动文件。
