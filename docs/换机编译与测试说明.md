# 换机编译与测试说明

## 本机故障结论（2026-10-20）

本项目是 ROS 2 包 `danmucamera`，源码目录叫 `qiji`。本机曾在激活 Miniforge `base` 环境时执行构建，出现两层故障：

1. CMake 选中 `/home/cyf/VLA/miniforge3/bin/python3`（Python 3.14），该解释器没有 `catkin_pkg`，在 `ament_package()` 阶段报 `ModuleNotFoundError: No module named 'catkin_pkg'`。
2. 改用系统 Python 后，旧 CMake 缓存仍指向 Conda 的 `fmt` 和 `spdlog`，链接时又加载 Conda 的 `libcurl`、`libicu`，出现 `CURL_OPENSSL_4`、`CXXABI_1.3.15` 未定义引用。

已修正 `launch/build.sh`：默认指定系统 Python；检测到 Conda 环境时，从构建进程的 `PATH` 中移除该环境，并在 CMake 缓存含 Conda 路径时清理此包的旧构建目录。本机重新执行 `./launch/build.sh` 后结果为 `Summary: 1 package finished`，四个可执行目标均构建成功，RealSense 与 Orbbec 后端均启用。图形程序和 ROS 节点也已启动验证；本机相机节点成功打开 Gemini 设备。没有验证标定精度或完成整套采图流程。

## 新电脑准备

以下命令针对 **Ubuntu 22.04 + ROS 2 Humble**。复制项目后，在新电脑的图形桌面终端运行这一条命令即可安装依赖、编译并启动（首次需要联网和 sudo 密码）：

```bash
cd /你的路径/qiji && ./launch/setup_and_run.sh
```

脚本会安装 Qt 6、OpenCV、colcon、ROS 2 Humble 等系统包；若系统还没有 ROS 软件源，会按 ROS 官方流程配置。它不会自动安装厂商相机 SDK。其他系统请安装对应发行版的同类依赖。若要手动安装，先安装 ROS 2 Humble 并完成其官方环境配置，再安装构建依赖：

```bash
sudo apt update
sudo apt install build-essential cmake python3-colcon-common-extensions \
  python3-catkin-pkg python3-ament-package \
  ros-humble-ament-cmake ros-humble-rclcpp ros-humble-rcl-interfaces \
  ros-humble-sensor-msgs ros-humble-std-msgs ros-humble-std-srvs \
  ros-humble-launch ros-humble-launch-ros \
  qt6-base-dev libopencv-dev libopencv-contrib-dev v4l-utils
```

普通 V4L2 摄像头不需要厂商 SDK。若要用 RealSense，安装与相机匹配的 `librealsense2` 开发包和设备规则；若要用 Orbbec Gemini，安装 **Orbbec SDK v2** 的头文件、动态库和设备规则。SDK 缺失只会关闭对应后端，不影响 V4L2 编译。安装 SDK 后重新插拔相机。新电脑上的 SDK 若不在系统搜索路径，可设置 `CMAKE_PREFIX_PATH` 指向其安装前缀。

## 复制与编译

复制本目录的 `CMakeLists.txt`、`package.xml`、`src/`、`config/`、`launch/`、`docs/` 和 `README.md`。不要复制 `build/`、`install/`、`log/`；它们包含旧电脑的绝对路径。`samples/` 和 `result/` 是个人数据，按需复制。项目路径允许变化。

```bash
cd /你的路径/qiji
source /opt/ros/humble/setup.bash
./launch/build.sh
./launch/run.sh
```

`build.sh` 默认使用 `/usr/bin/python3`。如果 ROS 2 安装方式需要另一解释器，先确认它能执行 `import catkin_pkg, ament_package`，再设置 `ROS_PYTHON_EXECUTABLE=/该解释器的绝对路径`。避免在构建时把 Conda 库放进 `CMAKE_PREFIX_PATH`、`LD_LIBRARY_PATH` 或 `PKG_CONFIG_PATH`。需要彻底重编译时，可在项目根目录删除本地产物后再构建：

```bash
rm -rf build install log
./launch/build.sh
```

## 验收顺序

1. 构建输出应有 `Summary: 1 package finished`；`install/danmucamera/lib/danmucamera/` 下应有 `io_node`、`calibration_bridge`、`calibration_ui`、`calibration_solver`。
2. 运行 `./launch/run.sh` 后，终端应出现三个节点的 `process started`，并显示标定界面。关闭界面时，其余两个节点会随之退出。请在有桌面会话和显示权限的终端运行。
3. 用 `v4l2-ctl --list-devices` 确认普通摄像头可见；厂商相机先用 SDK 自带示例验证采流，再在界面中刷新、选择设备和分辨率、连接并启动，确认出现实时画面。
4. 导入测试图片或拍摄几张图片，检查预览、保存和标定结果。新相机、每种分辨率以及 RGB/红外成像器都应分别标定。

如构建输出缺少 `RealSense SDK backend enabled` 或 `Orbbec SDK v2 backend enabled`，表示对应开发库未被 CMake 找到。检查 SDK 的头文件、动态库及 `CMAKE_PREFIX_PATH`，然后删除 `build/danmucamera/` 再编译。

## 常见报错

| 现象 | 处理 |
| --- | --- |
| `No module named 'catkin_pkg'` | 用 `/usr/bin/python3 -c 'import catkin_pkg, ament_package'` 检查系统 Python；安装上面的 Python 包，重新运行 `build.sh`。 |
| `CURL_OPENSSL_4` 或 `CXXABI_1.3.15` 链接错误 | 检查 Conda 是否污染 `PATH`、`CMAKE_PREFIX_PATH`、`LD_LIBRARY_PATH`；退出 Conda，删除 `build/danmucamera/`，重新构建。 |
| `could not connect to display` / Qt `xcb` 错误 | 在已登录的图形桌面终端运行，并确认 `DISPLAY` 与 X11/Wayland 显示权限。无桌面容器无法验证界面。 |
| ROS `Error creating socket: Operation not permitted` | 容器或沙箱禁止网络套接字；在允许 ROS 2 DDS 通信的正常桌面环境运行。 |
| 设备存在但无图像 | 检查 USB/udev 权限、SDK 示例、分辨率和帧率、设备是否被其他程序占用。 |

构建日志在 `log/latest_build/`，运行日志在 `log/ros/`。提交求助信息时附上对应日志、Ubuntu/ROS 版本和所用相机型号。
